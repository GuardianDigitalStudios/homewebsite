Hard constraints

Things any design for this site must satisfy. These are not preferences, each one has already broken the live site at least once.

Inline styles do not work The site sends Content-Security-Policy: style-src 'self' with no 'unsafe-inline', so browsers silently discard every style="…" attribute. This shipped: the footer wordmark was styled inline, the attribute was dropped, and the words "Guardian" and "Studios" rendered in the footer's own background colour, invisible in production while looking perfect locally over file://.
  • Every visual property needs a class in a stylesheet.
  • An inline <style> block is blocked too.
  • Verify against a server sending the real CSP header, not a local file.
Text contrast is measured, not eyeballed Four footer values failed WCAG AA at once, the worst being the company name at 2.36:1 against its own background. AA needs 4.5:1 for text under 18.66px.
  • Dark grounds and light grounds need separate muted roles. One value cannot serve both, measured, the light-page muted colour hit 2.70:1 on the dark footer, and the dark-footer one hit 2.90:1 on the page.
Fonts Loaded from Google Fonts, which the CSP explicitly allows (style-src … fonts.googleapis.com, font-src … fonts.gstatic.com). Currently Outfit and JetBrains Mono. A different family is fine; a self-hosted or third-party CDN font needs the CSP updated with it.
Hosting Static files on Cloudflare Pages. No build step, no framework, plain HTML, one stylesheet, one small script. Anything requiring compilation is a new toolchain.
Logo images/transparent_logo.png, a blue shield mark, real alpha channel, no text baked in. There is also logo.jpg, an opaque white-background version whose artwork contains the company name in illegible micro-type; it should not be used on any coloured ground.
