Motion and behaviour

All of it. script.js is 19 lines and does exactly one thing, the mobile menu. Everything else here is a CSS transition. There is no @keyframes rule anywhere on the site and nothing animates on load.

Behaviour (script.js)

BehaviourDetail
Mobile menuThe burger toggles an open class on #navLinks and syncs aria-expanded. Any link closes it.
EscapeCloses the menu when it is open.
Click awayA click outside <nav> closes it. The handler returns early for anything inside <nav>, because the burger's own click bubbles to document and would otherwise fight toggleMenu() and leave the menu shut on every attempt to open it.

Easing and durationsOne curve, --ease: cubic-bezier(.2,.6,.2,1). Three durations are defined, --fast 120ms, --base 220ms and --slow 420ms; --slow is currently unused. Nothing on the site transitions for longer than 220ms.
Reduced motion is honoured@media (prefers-reduced-motion:reduce) collapses animation-duration and transition-duration to .01ms and forces scroll-behavior:auto, universally. An earlier version of this page listed the absence of that rule as an open defect. It was added; the defect is closed.
Do not measure max-height in the tick you add the classReading the computed max-height of nav ul immediately after open is added returns 0px, because that is the animation's first frame. The menu was reported broken twice on that basis and was working the whole time. Disable transitions, or wait a frame, before believing the value.

The 260px ceiling is also a link count: about 51px per link, so four fit with room for one more, and a sixth clips silently. See Navigation.

History: what was removed, and why it is not coming back
  • Scroll reveal. Elements were given opacity:0 in CSS and only an IntersectionObserver brought them back, so if the script failed to run the About and Products sections stayed permanently invisible and the page rendered as a hero above a footer with nothing between. That is a bad trade for a fade, and worse on a site whose job is being the SEO front door. It also actually reproduced: headless screenshots came back blank.
  • A scrolled class on the nav. The bar is translucent and blurred at every scroll position now, so the class had nothing left to change and its scroll listener was deleted.
  • Hero entrance fade and a badge pulse. Both gone with the stylesheet that defined them. No @keyframes survives.

Nothing in CSS may hide content that only JavaScript restores. If a future design wants entrance motion, animate from visible, or set the hidden state from JavaScript so a no-JS render shows content rather than hiding it.
