Motion and behaviour

All of it. The site runs about 25 lines of JavaScript and this is what they do.

BehaviourDetail
Sticky navGains a scrolled class past 20px, which currently adds a shadow
Mobile menuHamburger toggles an open class; any link closes it
Scroll revealElements marked .reveal start at opacity: 0 and translateY(30px), then transition in over 0.7s when 15% visible. Siblings stagger 80ms apart.
Hero entranceHeadline and sub fade down on load, staggered 0.1s / 0.2s
Badge pulseA 2s infinite opacity pulse on a small dot
Defect: reduced motion is not honoured There is no prefers-reduced-motion rule anywhere in the stylesheet. Every animation above plays regardless of the visitor's system setting. Whatever the new design does with motion, it needs that media query.
Risk: content is hidden until JavaScript reveals it .reveal sets opacity: 0 in CSS, and only the IntersectionObserver adds the class that brings it back. If the script fails, is blocked, or never runs, the About and Products sections stay permanently invisible, the page renders as a hero and a footer with nothing between them.
  • This is not hypothetical: it is exactly what happened when the page was screenshotted headlessly, and the sections came back blank.
  • It also affects anything that reads the page without executing scripts, which matters for a site whose job is being the SEO front door.
  • The robust pattern is to animate from visible, or to set the hidden state from JavaScript so a no-JS render shows content rather than hiding it.
